# P3.1 — Create Product Requirements

Read `../GUIDELINE.md`, `../../AGENTS.md`, the accepted Project Brief and accepted Project Context.

Create a concise PRD defining problem, actors, core journey, scope, exclusions, prioritized requirements, invariants, observable acceptance criteria, assumptions, open questions and traceability.

Do not invent behavior or choose architecture, API, database or UI. Save `docs/product-requirements.md` as `Draft — Pending Human Review`. Human approval is required.
