# Project Guide

## Development Workflow

RideShareHub follows an artifact-driven AI-assisted
software engineering workflow.

Stages:

1. Project Brief
2. Project Context
3. Requirements & Product Analysis
4. Product Design
5. Software Architecture
6. Coding & Pair Programming
7. Review & Refactoring
8. Software Testing

Do not skip stages that introduce product or architecture decisions.

## Canonical Artifacts

Each chapter produces an Accepted artifact.

The next chapter must read the accepted artifacts directly.

Do not use phrases such as:

"as discussed previously"

as a replacement for project context.

## Human Authority

AI output is a draft.

The human accepts, rejects or modifies decisions.

AI must not mark review-gated artifacts as Accepted without
explicit human approval.

## Scope

Do not silently add functionality.

If requested behaviour is outside accepted scope,
report the scope impact before changing canonical artifacts.

## Current Product

RideShareHub is a multi-operator shared ride booking platform.

Detailed product information belongs in canonical project docs,
not in this rule file.
